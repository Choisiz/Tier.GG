## 1. 이 폴더는 무엇인가

- 요약: 분석 결과(유형·과목·좋음/부족)를 **어떻게 해석하고, 어떤 장면이면 다음 판에 무엇을 할지**(조건 + 구체 행동)를 짧게 적은 조각들이다. 분석할 때 그 판에 맞는 조각을 찾아 LLM에 함께 준다 (ai_spec B4).
- 판정(점수·등급)과 숫자는 코드가 정한다. 조각은 문장의 **해석·조언 근거**로만 쓰인다.
- 파일 = 유형 하나(10개) + `common.md`(모든 유형 공통). 지금 **81조각** (Claude 초안 65개를 사용자가 받아들이고, 유형 조각이 없는 교전·운영 과목 × 좋음/부족에 공통 조각 16개를 더함, 2026-11-04). DB 적재 완료. 2026-11-10(Q2)에 81개 모두 "조건 + 구체 행동" 꼴로 다시 쓰고 다시 적재했다(ID는 그대로).
- 유형 파일에 해당 과목 조각이 없으면 `common.md`의 같은 과목 조각(`ALL`)이 쓰인다. 둘 다 없으면 그 과목은 조각 없이 쓴다.

## 2. 검수 방법 (사용자)

1. 아래 4장 표로 빠지거나 이상한 관점을 먼저 훑는다 (상황 + 조건과 행동).
2. 파일을 열어 본문을 롤 지식으로 고친다. 고친 문서가 정답이다. 필요하면 조각을 더하거나 지운다.
3. 고친 뒤 `cd backend && npm run rag -- ingest --offline`으로 형식을 검사한다 (네트워크 없음). 오류가 있으면 줄 번호와 이유가 나온다.
4. 조각 ID를 바꾸거나 지웠다면 검색 평가 세트 `backend/test/eval/rag-eval.json`의 expected도 고친다 (`npm run rag -- eval --check`로 확인).
5. 고친 뒤 `npm run rag -- ingest`(미리보기) → `npm run rag -- ingest --yes`로 바뀐 조각만 다시 적재한다. 지운 조각까지 DB에서 빼려면 `--prune --yes`.

## 3. 쓰는 규칙

| 항목 | 규칙 |
|------|------|
| 모양 | `### <ID> <제목>` 다음 줄에 `- meta: role=..., area=..., subject=..., polarity=...`, 그다음 본문 |
| ID | `<과목ID>.<유형>.<good\|bad>.<두 자리>` (예: `fight.damage.SUPPORT_DAMAGE.bad.01`). 공통은 유형 자리에 `ALL` |
| 값 | role: 유형 10개 또는 `ALL` · area: `laning` `fight` `macro` · subject: 엔진 과목 ID(`laning.gold` `fight.damage` `macro.vision` 등 13개) · polarity: `good` `bad` |
| 본문 | 2~5문장, 600자 이하. **한 조각에 한 관점만** |
| 숫자 | **쓰지 않는다** (오류로 막힘). 경계값은 `backend/src/analysis/rules.ts`만. 숫자가 있으면 LLM이 섞어 쓸 수 있다 |
| 말투 | 해석은 단정 대신 "~일 수 있다". 조언은 **조건 + 구체 행동**: "(이 판의 장면이) ~였다면, 다음 판에는 (언제) (어디서) (무엇을) 한다." 장면 조건은 엔진 장면 facts(오브젝트 시각·종류·잡은 팀·그 전 60초 내 와드, 내가 참여한 싸움의 처음 죽은 사람·지역, 단독 킬·데스와 라인전 데스의 지역·상대 정글 관여)로 확인할 수 있는 것만 쓴다 (Q2) |
| 막는 말 (오류) | 은어 "낀"(→ "참여한"), 막연한 조언 "~볼 수 있다", "이어 가". 쓰면 `ingest`가 **오류**로 막는다 (Q2) |
| 피할 말 | 검증기가 막는 해석어(이니시, 버스, 캐리, 무리, 던지다, 실수, 판단, 집중력, 욕심)와 등급·점수·총점·반영 비율. 쓰면 경고가 나온다. 챔피언·아이템·룬·스킬 이름도 쓰지 않는다 |
