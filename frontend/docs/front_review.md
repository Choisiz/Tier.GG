## 2. 발견한 문제

### 2-1. (수정함) 모바일 탭이 처음엔 툴팁을 열지 못함 — `Tooltip.tsx`

- **증상**: 포커스되지 않은 트리거(룬·스킬·주문·아이템 아이콘)를 모바일에서 처음 탭하면 툴팁이 열리지 않는다. 같은 트리거를 한 번 더 탭해야 열린다.
- **원인**: 터치 탭은 브라우저가 `focus` 이벤트를 먼저 보내고 바로 뒤이어 `click` 이벤트를 보낸다. `onFocus`가 `setOpen(true)`를 호출한 직후, 같은 탭의 `onClick`이 `setOpen(prev => !prev)`로 **그 값을 다시 토글**해 `true → false`가 되어 버린다. 실제 브라우저(모바일 뷰포트 375px, 터치 에뮬레이션)에서 재현했고, `document.activeElement.getAttribute('aria-describedby')`가 첫 탭 직후 `null`(닫힘), 두 번째 탭 후에야 값이 채워짐(열림)을 확인했다.
- **완료 기준과의 관계**: 10장 "모바일 뷰포트(360px)에서 탭으로 열리고 바깥 탭으로 닫힘"에 직접 위배되고, D15("모바일(터치)에서 탭하면 토글")의 의도(첫 탭 = 열림)와도 어긋난다.
- **조치**: 작은 범위의 명확한 버그라 직접 고쳤다 (설계 변경 아님, 로컬 ref 하나 추가). `onFocus`가 연 상태임을 `openedByFocusRef`에 표시해 두고, 바로 뒤따르는 `onClick`이 "이 탭의 포커스가 막 열었다"는 걸 알면 다시 토글하지 않도록 했다. 두 번째 탭부터는(이미 포커스된 상태라 `onFocus`가 재발화하지 않음) 정상적으로 토글된다.
- **재확인**: 375px 터치 에뮬레이션에서 (a) 처음 보는 트리거 첫 탭 → 열림, (b) 같은 트리거 재탭 → 닫힘(토글), (c) 다른 곳 탭 → 닫힘(바깥 탭) 세 가지 모두 `aria-describedby`/`role="tooltip"` DOM 상태로 확인. 데스크톱 호버·키보드 포커스/블러 동작은 수정 전후 그대로(회귀 없음) — 호버는 `onMouseEnter`/`onMouseLeave`만 쓰고 수정 대상인 `onClick`을 거치지 않으며, 키보드 Tab은 Enter 키가 `<span>`에서 `click`을 발생시키지 않아 `onFocus`/`onBlur`만으로 동작하므로 이번 수정과 경로가 겹치지 않는다.

### 2-2. (기록만) `/champions/Foo`가 `next dev`에서 200을 반환함

- `npm run dev`(포트 3000, 이미 떠 있던 세션)로 `/champions/Foo`를 요청하면 HTTP 200 + `x-nextjs-cache: HIT`가 나온다. 같은 코드를 운영 빌드(`next start`, 포트 3001)로 띄우면 정상적으로 404를 반환한다.
- 이번 변경이 건드린 `notFound()` 호출(`page.tsx:122`)은 수정되지 않았고, 완료 기준 검증은 운영 빌드 기준이라 **블로커 아님**. dev 서버의 알려진 캐싱 동작으로 보이며 변경 03과 무관해 코드 수정을 하지 않았다.

### 2-3. (기록만) `/champions/Aatrox` LCP가 2.98s → 3.15s로 약간 나빠짐

- Build가 승인받은 D14(스킨 캡션을 위해 `ChampionHero`를 client 컴포넌트로 전환)의 알려진 트레이드오프로 보인다. LCP 이미지 자체는 여전히 초기 HTML에 `fetchpriority="high"`로 discoverable했다(4장, `lcp-discovery-insight` 통과). 블로커로 보지 않았고 수정하지 않았다 — `front_overview.md` 해결되지 않은 점에 반영.

## 3. 브라우저 확인

조건: 내장 브라우저, 백엔드 4000(실 데이터, 14일 3,789게임 스냅숏), `npm run dev`(3000)와 `npm run build && npm start`(3001, 검증용) 모두 사용.

- **레이아웃**: 1280px에서 룬 카드(좌, 전체) + 소환사 주문(우상)·스킬 순서(우하) 2단, "많이 완성한 아이템"이 그 아래 전체 폭 카드로 분리됨을 스크린샷으로 확인. 768px·360px은 룬→주문→스킬→아이템 1열, `document.documentElement.scrollWidth === clientWidth`로 가로 스크롤 없음 확인(360/768/1280 모두).
- **스킨 전환**: 아트록스 13개 스킨, ‹ › 클릭마다 스플래시와 "스킨: {이름} (n/13)" 캡션이 함께 갱신됨. 1번째에서 ‹ 클릭 → 13/13(뒤로 순환), 13번째에서 › 클릭 → 1/13(앞으로 순환) 모두 확인.
- **룬 화면**: 핵심 트리(크게) → "사용 42.8% · 승률 46.6% · 118게임" → 보조 트리 → 능력치 파편 순 세로 배치(가로 2단 그리드 없음). sr-only 요약 "핵심 룬(정밀): 정복자, 승전보, 전설: 가속, 최후의 저항…"이 격자 강조 순서와 일치(변경 02 로직 그대로 재사용, 영향 없음 확인).
- **스킬 격자**: 머리글 "레벨/Q/W/E/R", 본문 11행×4열. 아트록스 `QEWQQRQEQER`와 레벨 1~11 칸 위치 일치, 오공(`MonkeyKing`) Q 아이콘(`MonkeyKingDoubleAttack.png`) 포함 4개 아이콘 깨짐 없이 렌더링 확인.
- **아이템**: 아트록스 핵심 3개(쇼진의 창·월식·갈라진 하늘, 롱소드·도란·물약·장신구 없음) + 신발(판금 장화, 사용률 70.7%). 징크스는 신발 칸이 아예 없음(사용률 5% 미만으로 숨김) 확인.
- **툴팁**: 호버(마우스 이동 후) → 룬·스킬·주문·아이템 설명 패널 표시. 키보드 Tab 포커스 → 같은 패널이 `aria-describedby`로 연결되어 열림, Tab으로 이동(블러)하면 닫힘. 데스크톱 포커스 링은 Tailwind `focus-visible:outline-none`에도 불구하고 전역 비-레이어 CSS 규칙(`globals.css`)이 우선 적용되어 금색 2px 링이 정상적으로 보임(캐스케이드 레이어 우선순위 확인). 모바일(375px, 터치 에뮬레이션) 탭 토글은 2-1 결함을 찾아 수정 후 재확인.
- **포지션 탭**: 카밀(탑 1티어 61% / 서폿 5티어 37%)에서 두 번째 탭 클릭 시 요약 줄·룬·주문이 해당 포지션 데이터로 전환됨을 확인(해당 컴포넌트는 이번 diff에서 미수정, 회귀 없음 확인 목적).
- **404**: `/champions/Foo` — 운영 빌드(3001)에서 HTTP 404 확인. "챔피언을 찾을 수 없습니다" + 목록 링크 표시.
- **콘솔/네트워크**: `read_console_messages`로 오류 0건, Data Dragon 이미지 요청(스킬·소환사 주문) 전부 200/304, 깨진 이미지 없음.
