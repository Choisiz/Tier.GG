## 6. 지켜야 할 규칙

- 판단은 코드, 문장은 LLM, LLM 답의 숫자는 코드가 검증한다 (CLAUDE.md 12장).
- 경계값·비율은 `rules.ts`에만 둔다. 바꾸면 `feedback_design.md` 결정 사항과 `ENGINE_VERSION`을 함께 바꾼다.
- 설계 숫자와 코드 결과가 다르면 테스트를 코드에 맞추지 않고 보고해 사용자가 정한다.
- 유료 API 실행은 예상 비용을 먼저 보여 주고 승인받는다.

## 8. 해결되지 않은 점

1. 딜 구간 평균 등급이 정확히 중간이면 높은 등급으로 올린다(D + A → B). Build가 정한 해석이라 사용자 확인이 필요하다.
2. 다시하기(조기 항복) 판을 거르지 않는다. 5단계 전 "분석할 판 범위"를 정할 때 함께 정한다.
3. 실제 값으로 검증한 판이 세나 판 하나뿐이다. 손검산 판을 더 넣으려면 Riot 원본이 필요하다.
4. 총점 경계 70·40은 초안이다. 실제 판 총점 분포를 보고 맞춘다.
5. 중후반 파밍 경계(분모 약 4% 차이)와 교전 이득 평균 수치(수정 전 값)는 다음 경계 재보정 때 다시 계산한다.
6. 세트(서폿) 덮어쓰기는 표본이 1명이라 보류했다.
7. 5단계 API에서는 판 패치 버전에 맞는 Data Dragon 태그를 공급할 방법이 필요하다 (지금은 테스트용 16.21.1 스냅숏).
