## 2. front_spec.md 복원 사고 판정

판정: **손상·누락 없음. 단, 결정 표가 끊기는 서식 결함 1건.**

근거:
- `git diff HEAD` 기준 삭제된 줄은 9개뿐이고 전부 의도한 수정이다(상태 헤더 2줄, 디렉토리 트리·5-7 매치 행 표·Build 작업 범위 같은 한 줄 갱신 등). 나머지는 순수 추가(+243줄)다. 즉 커밋된 기존 내용(HEAD 724줄, 240~730줄 구간 포함)은 한 줄도 사라지지 않았다. 지금 파일은 958줄이다(복원 직후 1048줄이었다는 보고와 줄 수가 다르다. 이후 Build가 줄여 정리한 것으로 보이며, 추가분 5-8·5-9는 아래대로 내용이 이어진다).
- 목차의 모든 항목(1~13장, 5-1~5-9)이 실제 제목과 일치하고 장 번호가 연속이다. 코드블록 펜스 10개(짝수)로 닫히지 않은 블록이 없다.
- 결정 표: D1~D44(D3-b·D23(정정) 포함) 연속, D45~D48은 "하지 않기로 한 결정" 표로 따로 있고, D49~D65 연속. 중복·누락 없음. D54~D58(변경 07 후속)은 5-8 후속 1·2 절의 설명과 일치한다.
- 임시 `## 이번 변경 (승인 대기)` 절은 남아 있지 않다(5행·13장 표의 해당 문구는 "다음에 이렇게 쓴다"는 안내문이다).
- 5-9 본문은 구현과 일치한다(4줄 16/16/20/16px, 색 기준 52/48~51/47, 재시도 규칙, 상태 표).

**결함(중요, 문서 렌더링)**: 11장 결정 표에서 D38 행 다음 줄(884행)에 `---` 가로줄이 끼어 있어 D39~D65 행이 표 머리 없이 일반 글자로 렌더링된다. 원래 12장 앞에 있던 구분선이 새 행 앞으로 잘못 들어간 것으로 보인다. 884행의 `---`와 앞 빈 줄을 지우고 D65 행 뒤(12장 앞)로 옮기면 된다. 내용은 전부 남아 있어 복구가 아니라 서식 수정이다. Build 몫으로 남긴다.

## 4. 접근성

- 색에만 의존하지 않는다: 라인전은 항상 `45:55` 숫자를 병기하고 `sr-only`에 "내 쪽 N 상대 쪽 M"을 읽어준다. 승/패 요약은 색+글자다.
- 툴팁은 `Tooltip`의 `tabIndex=0` + `onFocus`로 키보드로 열린다(변경 03 이후 확인된 패턴, 이번 확인은 코드와 포커스 이벤트 기준).
- 로딩 막대는 `prefers-reduced-motion`이면 정지한다.
- 경미: 행마다 키보드 정지점이 2개(킬관여·라인전) 늘어 20행이면 40개다(7장 3번).

## 6. 사용자 흐름

- 새로고침: 같은 `puuid`로 새로 마운트되어 다시 요청하지만 백엔드 캐시가 응답한다. Build 로그 기준 `riotCalls=0`.
- 다른 소환사로 이동: `key={puuid}`로 컴포넌트가 새로 만들어지고 이전 요청·대기는 cleanup에서 취소되어 상태가 섞이지 않는다.
- 0게임: `MatchList`가 안내문을 반환해 Provider·요청이 없다. 요약 카드도 `matches.length > 0`일 때만 나온다.
- 20게임 미만(예 7게임): `chunkIds`가 한 묶음으로 처리하고 효과는 같다.
- 전부 5분 미만: 요약은 "요약할 게임이 없습니다", 라인전은 백엔드가 `unavailable`을 주면 `-`.
