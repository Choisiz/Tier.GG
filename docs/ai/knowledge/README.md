## 1. 이 폴더는 무엇인가

- 요약: **조언 규칙(R1~R5)마다 그 규칙이 무엇을 뜻하고 무엇을 하라는지** 풀어 쓴 해설 조각이다 (ai_spec Q3, 2026-11-11). 분석할 때 그 판의 칸에서 **발동한 규칙의 조각만** 찾아 LLM에 함께 준다.
- 판정(점수·등급)·숫자·조언을 할지 말지는 코드(`backend/src/analysis/advice.ts`)가 정한다. 조각은 그 규칙을 문장으로 옮길 때의 **해설**로만 쓰이고, 조각에 없는 원인이나 행동은 쓰지 않는다.

| 규칙 | 근거 (feedback_design) | 붙는 칸 | 뜻 |
|------|------|------|------|
| R1 | 반영 비율 (5-1, 6-2) | 교전·운영 과목 부족한 점 | 이 유형에서 비중(반영 비율 30 이상)이 큰 과목이 부족했고 상대 라이너보다 낮았다 → 그 과목에 신경 쓴다 |
| R2 | 득실 점수 (5-4) + 딜 등급 | 교전 딜·득실 부족한 점 | 딜도 기대보다 낮고 내 데스가 상대 득실이 됐다 → 오브젝트 싸움에서 죽지 않을 위치를 잡는다 |
| R3 | 득실 점수 (5-4) + 딜 등급 | 교전 득실 부족한 점 | 딜은 높았지만 내 데스가 상대 득실이 됐다 → 이런 데스가 역전의 시발점 |
| R4 | 첫 데스 해석 (5-4-1) | 교전 득실 좋은 점·부족한 점 | 먼저 죽은 사람(탱/딜러)과 결과로 5-4-1 문장 그대로. 해석만, 행동 조언 없음 |
| R5 | 단독 킬·데스 (6-1) | 운영 단독 킬·데스 부족한 점 | 혼자 싸워 죽은 장면 → 그런 상황에서 혼자 싸우지 않는다 |

- 파일 = 유형 하나(10개, 그 유형의 R1 조각 2개) + `common.md`(모든 유형 공통, 규칙마다). 지금 **34조각**(공통 14 + 유형 20). 라인전과 좋은 점(R4 제외)에는 규칙이 없어 조각도 없다. 2026-11-11(Q3)에 81조각을 이 34조각으로 바꾸고 적재했다(옛 81조각은 DB에 남아 있지만 규칙 칸이 없어 검색에서 버려진다. 지우려면 `--prune --yes`).
- 유형 파일에 해당 과목·규칙 조각이 없으면 `common.md`의 같은 과목·규칙 조각(`ALL`)이 쓰인다.

## 2. 검수 방법 (사용자)

1. 아래 4장 표로 빠지거나 이상한 관점을 먼저 훑는다 (규칙 · 상황 · 행동).
2. 파일을 열어 본문을 롤 지식으로 고친다. 고친 문서가 정답이다. 필요하면 조각을 더하거나 지운다.
3. 고친 뒤 `cd backend && npm run rag -- ingest --offline`으로 형식을 검사한다 (네트워크 없음). 오류가 있으면 줄 번호와 이유가 나온다.
4. 조각 ID를 바꾸거나 지웠다면 검색 평가 세트 `backend/test/eval/rag-eval.json`의 expected도 고친다 (`npm run rag -- eval --check`로 확인).
5. 고친 뒤 `npm run rag -- ingest`(미리보기) → `npm run rag -- ingest --yes`로 바뀐 조각만 다시 적재한다. 지운 조각까지 DB에서 빼려면 `--prune --yes`.

## 3. 쓰는 규칙

| 항목 | 규칙 |
|------|------|
| 모양 | `### <ID> <제목>` 다음 줄에 `- meta: role=..., area=..., subject=..., polarity=..., rule=...`, 그다음 본문 |
| ID | `<과목ID>.<유형>.<good\|bad>.<규칙>` (예: `fight.vision.SUPPORT_DAMAGE.bad.R1`). 공통은 유형 자리에 `ALL`. 같은 규칙 조각이 여럿이면 `R1-2` |
| 값 | role: 유형 10개 또는 `ALL` · area: `fight` `macro` · subject: 엔진 과목 ID · polarity: `good` `bad` · **rule: `R1`~`R5` (필수)**. 규칙마다 붙을 수 있는 과목·방향은 1장 표 (어기면 오류) |
| 본문 | 2~5문장, 600자 이하. 규칙의 뜻 + 규칙 요지에 있는 행동만. **데이터가 말하지 않는 원인은 쓰지 않는다** |
| 숫자 | **쓰지 않는다** (오류로 막힘). 경계값은 `backend/src/analysis/rules.ts`만 |
| 막는 말 (오류) | 은어 "낀"(→ "참여한"), 막연한 조언 "~볼 수 있다", "이어 가" |
| 피할 말 | 검증기가 막는 해석어(이니시, 버스, 캐리, 무리, 던지다, 실수, 판단, 집중력, 욕심)와 등급·점수·총점·반영 비율. 쓰면 경고가 나온다. 챔피언·아이템·룬·스킬 이름도 쓰지 않는다 |
