## 1. 한눈에 보기

- 요약: 기능 1 "게임 피드백"의 **1단계 판정 엔진**(Review 통과)과 **2단계 LLM 문장 + 숫자 검증 + 템플릿**(Review 조건부 통과)이 있다. 한 판을 넣으면 엔진이 판정하고, Claude(`claude-opus-5-5`, effort `low`)가 칸마다 문장만 쓰고, 코드가 숫자·방향·금지어·길이·이름을 검사해 틀린 칸만 1번 다시 쓰게 하고, 그래도 틀리면 템플릿 문장으로 바꾼다. RAG·DB·API·화면은 아직 없다.
- 2단계 기준선(RAG 없음, 5판 54칸): 1차 통과 51/54(94.4%), 숫자 1차 통과 52/54(96.3%), 재시도 3칸 모두 통과, 템플릿 0, 검증기 기준 최종 틀린 숫자·방향·금지어 0. 판당 평균 $0.074, 13.7초. 장부 누적 $0.4461 / 2단계 상한 $1.00.
- 남은 조건: 사용자 채점(근거 없는 주장), 그리고 숫자 검증을 통과했지만 오해를 부르는 문장 3개(앞선 팀이 바뀐 결정적 장면, 팀 킬을 "데스"로 쓴 것)의 처리 방향 결정.

## 4. 구조

```
AnalysisResult(엔진) ─▶ facts.ts(쓸 수 있는 숫자·이름, 등급·점수 제외) ─▶ prompt.ts(고정 시스템[캐시] + 판정 JSON)
  ─▶ client.ts(Claude 1회, 구조화 출력, effort low, thinking 생략) ─▶ verify.ts ─┬ 통과 → mode "llm"
                                                                               └ 실패 칸 → 재시도 1회(앞 대화 덧붙임, 고칠 칸만) → 또 실패 → template.ts
  오류·거절·잘림·키 없음·예산 초과 → 전체 템플릿 (mode "template", fallbackReason)
```

| 부품 | 핵심 규칙 |
|------|-----------|
| facts | 차이는 절댓값, 방향은 말로. 소수는 둘째·첫째 자리, 정수 반올림 %p 금지. 골드·격차만 어림(step 100) |
| 검증기 | 모양(칸·fact ID·칸별 허용 ID), 방향(요약 판정어·결정적 장면), 숫자(그 문장 factIds 값과만), 금지어(등급·총점·점수·반영 비율, 해석어는 "보입니다"), 길이(120자·2문장/요약 200자), 이름(내 챔피언·상대 라이너만) |
| 오류 | SDK 클래스로 분류: auth·billing(402)·model_not_found·bad_request·rate·server·timeout·network. 거절·잘림은 `stop_reason` |

## 7. 지켜야 할 규칙

- 판단은 코드, 문장은 LLM, LLM 답의 숫자는 코드가 검증한다 (CLAUDE.md 12장). facts에 등급·점수·총점·반영 비율을 넣지 않는다.
- 경계값·비율은 `rules.ts`에만. 바꾸면 `feedback_design.md` 결정 사항과 `ENGINE_VERSION`을 함께 바꾼다.
- 시스템 프롬프트·스키마·facts 표기를 바꾸면 `PROMPT_VERSION`을 올린다(녹화본·장부 보정이 버전별).
- 유료 실행은 미리보기 비용을 먼저 보여 주고 승인받는다. 단위 테스트는 가짜 클라이언트만. 프롬프트 수정은 모아서 한 번에, 실제 확인은 1판으로.
- `@anthropic-ai/sdk`는 `llm/client.ts`만 import, `analysis/**`는 `process.env`를 읽지 않는다.

## 9. 해결되지 않은 점

1. 근거 없는 주장 비율을 사용자가 5판 54문장 채점표로 채점해야 한다 (2단계 완료 기준 6).
2. 결정적 장면에서 앞선 팀이 바뀌면 "격차 300 벌어짐", "1,796 좁혀짐"처럼 실제 손해(약 4,400·3,600)를 작게 보이게 쓴다. facts에 우리 팀 기준 변화와 "역전" 여부를 넣을지 정해야 한다 (다음 `PROMPT_VERSION`).
3. 검증기가 단위를 안 봐서 상대 팀 킬 5를 "5데스"로 쓴 문장이 통과했다.
4. 검증기가 좋은 점·부족한 점 칸 안의 방향 단어를 안 본다. 부족한 점 칸에 "많았습니다"도 통과한다.
5. "두 배", "열한 번", "칠백", "3천" 같은 한글·배수 표현, 단독 등급 글자("D 수준")는 검증기가 못 잡는다 (실제 출력에는 없음).
6. 중후반 파밍 칸에 "15분" fact가 없어 5판 중 2판이 재시도했다. 다음 `PROMPT_VERSION`에서 넣으면 판당 약 $0.05 줄어든다.
7. 장부 $0.4461을 Anthropic 콘솔 사용량과 한 번 대조해야 한다 (사용자).
8. DB에 저장된 puuid가 지금 키의 Riot 응답 puuid와 달랐다. 키마다 다르게 암호화되는 것으로 추정되며, 기존 기능 영향은 `!백엔드`가 확인해야 한다.
9. `README.md` 2단계 절이 계획 전 내용(60자, 옛 fact ID, "계획 승인 지금")이라 갱신이 필요하다 (메인 에이전트).
10. 1단계에서 넘어온 것: 딜 구간 평균 동점 처리(D + A → B) 확인, 다시하기 판 거르기, 총점 경계 70·40 초안, 중후반 파밍·교전 이득 경계 재계산, 세트(서폿) 보류, 5단계 Data Dragon 태그 공급 방법.
