## 4. 구조

```
AnalysisResult ─▶ facts ─▶ (RAG 켜짐) retrieve: 질의 문장 → Voyage 임베딩 → search_rag_chunks → 조각 ≤8
  ─▶ prompt(고정 시스템 + 판정 JSON [+ <knowledge> 조각]) ─▶ Claude 1회 ─▶ verify(숫자·방향·단위·금지어·길이·이름 + 쓴 조각 ID가 준 조각 안인지)
  ─▶ 통과 → llm / 실패 칸 → 재시도 1회 → 템플릿.  검색 실패·3초 초과 → 조각 없이 진행
```

- 조각은 해석·조언의 근거로만, 숫자는 facts에서만. 첫 답 맨 위 `chunkUse: [{slot, chunkIds}]`로 쓴 조각을 받는다(칸마다 두면 구조화 출력 문법이 너무 커 400).

## 7. 지켜야 할 규칙

- 판단은 코드, 문장은 LLM, 숫자는 코드가 검증 (CLAUDE.md 12장). 지식 문서에 숫자 경계값을 쓰지 않는다 (경계는 `rules.ts`만).
- 프롬프트·스키마·facts 표기가 바뀌면 `PROMPT_VERSION`을 올린다. 지식 문서를 고치면 `rag ingest --yes`로 DB를 맞춘다(그 전까지 `knowledgeVersion`이 DB와 다름).
- 유료 실행(Anthropic·전체 재적재)은 예상 비용을 보여 주고 승인 뒤에. 단위 테스트는 가짜 클라이언트.
- `process.env`는 CLI·`config/env.ts`·`server.ts`에서만. `ingest --prune`은 명시할 때만 지운다.

## 9. 해결되지 않은 점

1. 사용자가 RAG 5판 채점표(조언 구체성·근거 없는 주장)를 채점해야 RAG를 기본으로 켤지 판단할 수 있다. 지금은 비용 +27%, 1차 통과 소폭 하락이다.
2. 검색 평가가 필터에 거의 정해져 벡터 검색의 질을 아직 못 쟀다. 같은 과목·방향 후보가 3개 이상 되는 문항을 더한다.
3. API 검색 시간 초과 시 DB 질의가 계속 돈다(`withTimeout`은 기다림만 끝냄). 켜기 전 `statement_timeout`·풀 크기를 정한다.
4. Voyage 무료 등급 분당 한도로 API에서 429 → RAG 없이 진행이 잦을 수 있다. 서비스로 켜기 전 결제 등록 여부를 정한다 (사용자).
5. `chunkUse`의 같은 칸 중복 조각 ID가 제거되지 않는다 (사용 통계만 영향). `--replay` 결과의 비용이 녹화 비용으로 표시돼 혼동된다.
6. 넣은 조각 40개 중 28개만 쓰였다. 상한을 6개로 줄이거나 장면·요약용을 빼면 토큰을 아낄 수 있다. 탱탑 요약이 1위 아닌 장면 fact를 쓴 재시도, 파밍 "15분" fact 부재는 다음 프롬프트 버전 후보.
7. 장부 $1.3429를 Anthropic 콘솔 사용량과 대조 (사용자). 상한 $1.50까지 $0.16 남음.
8. DB puuid가 지금 키의 응답 puuid와 달랐던 문제의 기존 기능 영향은 `!백엔드`가 확인해야 한다.
9. 1단계에서 넘어온 것: 딜 구간 평균 동점 처리, 다시하기 판 거르기, 총점 경계 70·40, 중후반 파밍·교전 이득 경계 재계산, 세트(서폿) 보류.
